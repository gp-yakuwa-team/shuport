# ShuPort（シュポート）

就活の「調べる・書く・管理する」をひとつに。AIが企業研究とES作成を支援する、就活生向けWebアプリケーションです。

## 概要

ShuPort は、全業界を目指す就活生を対象とした就活支援Webアプリケーションです。

企業研究・エントリーシート（ES）作成・選考スケジュール・タスク管理は、本来それぞれ別のツールや手作業で行われがちで、「ESを書く前に調べるだけで疲れる」「締切や面接の管理が漏れる」といった負担の原因になっています。

ShuPort は、**企業を追加する（企業名・業界・募集要項を入力する）だけで、裏側でAIが自動で企業研究を実行・保存**し、その結果を見ながらESを書ける体験を目指しています。あわせて、選考カレンダー・タスク・LINE通知を一元化し、就活の管理漏れを防ぎます。

**目標**：ES作成にかかる時間を、従来の手作業（1社あたり約60分以上）から **30分以内（50%以下）** に短縮すること。

> 本システムは卒業制作として開発しています。公開期間は 2027年2月19日までを予定しており、期間終了時にすべてのデータを自動削除します。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| ダッシュボード | ログイン後に直近7日間の予定、接近する締切（3日前）、選考状況別の件数、未完了タスクを一目で確認 |
| 企業・選考状況管理 | 志望企業と選考ステータス（9種）を管理。企業詳細から研究結果・ES・採用サイト情報を参照 |
| AI自動企業研究 | 企業追加をトリガーに、バックグラウンドでAIが企業研究を自動実行（Google検索連携による最新情報＋出典リンク表示）。結果はカードとして保存され、同一企業は30日以内なら再利用 |
| ES作成支援 | 設問ごとのAI生成（初案・要約・文字数調整）で作成を支援。設問の追加・変更・並べ替えに対応し、1社に複数のESを作成可能 |
| 応募書類の出力 | ESをPDF、履歴書をExcel（.xlsx）で出力（本システムで保持しない個人情報の欄は空欄で出力し、利用者自身が端末上で入力） |
| 選考カレンダー | 面接・ES締切・説明会などの予定を統一フォーマットで管理。日程の重複と締切接近を検知してアラート |
| タスク管理 | 選考に紐づくToDoを管理し、ダッシュボードとLINE通知で未完了を可視化 |
| LINE連携・通知 | マイページ発行の6桁コードでLINE公式アカウントと連携。毎日20:00に翌日の予定・締切・未完了タスクをPush通知。LINEトークで送った日程は、内容を確認・承認したうえでカレンダーへ自動登録 |

## 技術スタック

| 分類 | 使用技術 |
| --- | --- |
| バックエンド | PHP 8.4 / Laravel 13 |
| フロントエンド | Blade / Tailwind CSS 4 / Vite |
| データベース | PostgreSQL（Supabase） |
| 認証 | Supabase Auth（メールアドレス＋パスワード、確認メール必須） |
| ホスティング | Render（Docker） |
| メインAI | Gemini API（有料枠 Tier 1。入力データが学習に利用されない構成） |
| サブAI | Cloudflare Workers AI（メインAIの障害時・上限到達時に自動切替） |
| 通知・連携 | LINE Messaging API |
| 認証メール | Gmail（Supabase Auth のカスタムSMTP） |
| 死活監視 | UptimeRobot / cron-job.org |

運用コストは、本番環境の Gemini API 利用料（月の費用上限を設定しチームで負担）を除き、無料枠の範囲で 0 円を維持する設計です。

## セキュリティ・プライバシー設計

- **データ最小化**：氏名・住所・電話番号・生年月日・顔写真は取得・保存しません
- **採用サイト情報の暗号化**：各企業の採用サイトのID・パスワードは AES-256 相当の可逆暗号化で保存し、暗号化鍵はデータベースと分離して環境変数で管理。外部AI・書類出力・LINE通知の対象からも完全に除外します
- **AI送信前のマスキング**：電話番号・メールアドレス等の個人情報らしき文字列を自動でマスクしてからAIに送信します
- **学習利用の排除**：本番環境の生成AIは、入力データが学習や製品改善に利用されない有料枠を利用します（無料枠は架空データのみの開発・検証環境に限定）
- **公開期間と全データ削除**：公開期間終了時および退会時に、関連データを完全に物理削除します

## 開発者向け情報

### 開発環境の要件

ローカルでの開発には以下のツールが必要です。

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows / Mac）
- Git

### ローカル環境のセットアップ手順

#### 1. リポジトリのクローン

```bash
git clone https://github.com/gp-yakuwa-team/shuport.git
cd shuport
```

#### 2. 環境変数の用意

実際のDB接続情報などは `.env.encrypted` で共有しています。復号に必要なキーはチーム内で別途共有しています。
手元で新規に用意する場合は、サンプルをコピーして作成してください。

```bash
cp.env.example.env
```

#### 3. 起動（Laravel Sail）

```bash
./vendor/bin/sail up -d
./vendor/bin/sail artisan migrate
```

※ 初回などで `vendor` が無い場合は、先に `composer install` が必要です（ホストに PHP / Composer が無い場合は、Sail 公式の Docker コマンドを利用してください）。

#### 4. フロントエンドの開発サーバー

```bash
./vendor/bin/sail npm run dev
```

### 本番環境

- ホスティング: Render（`Dockerfile.render` を使用）
- DB / 認証: Supabase（PostgreSQL / Supabase Auth）
- 起動時にマイグレーションを自動実行します

### 開発フロー

- PR の向き先は `develop` を基本とします
- ブランチ名: `feature/<内容>`、`fix/<内容>`、`chore/<内容>`、`docs/<内容>`
- PR タイトル: Conventional Commits 形式（`feat:` / `fix:` / `chore:` / `docs:` など）＋日本語の要約
- PR 本文: 変更内容と影響範囲を日本語で簡潔に書いてください（`.github/pull_request_template.md` が自動で挿入されます）
- マージ条件: CI（テスト・Pint）がグリーンであること

### テスト・コード整形

```bash
php artisan test
./vendor/bin/pint
```
